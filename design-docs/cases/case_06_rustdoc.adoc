== Design Tokens & Visual Grammar

=== Typography Scale & Pairing (Literary Academic Serif + Monospace)
Rustdoc is one of the very few modern documentation systems that **pairs an editorial serif face with an engineering monospace font**:
[horizontal]
Body Font Stack:: `"Source Serif 4", NanumBarunGothic, serif` (`--font-family`)
Code / Monospace Font Stack:: `"Source Code Pro", "Fira Mono", monospace` (`--font-family-code`)
Display / Heading Font:: `"Fira Sans", -apple-system, BlinkMacSystemFont, sans-serif`
Base Font Size & Line Height:: `16px` (`1rem`) with generous `1.6` line-height for prose paragraphs; headings use crisp Sans-Serif font weights.
Monospace Ratio:: Code signatures inside `.code-header` render at `100%` scale for clarity.

== 1. Granularity

=== Smallest Unit of Documentation
Rustdoc demonstrates **exhaustive compiler-level addressability**:
* **Every Trait Implementation has its own ID**: In `Mutex<T>`, the `impl<T: ?Sized> Mutex<T>` block has anchor `id="impl-Mutex%3CT%3E"`, and individual methods have anchors like `id="method.lock"` or `id="method.const_new"`.
* **Blanket Implementations Exposed**: Documents all universal trait implementations (`Any`, `Borrow`, `BorrowMut`, `From`, `Into`, `TryFrom`, `TryInto`) automatically generated by the Rust compiler.
* **Feature Flags Explicitly Tagged**: Unstable or optional cargo features are badged on individual methods (e.g. `Available on crate feature "tracing" only`).

=== Granularity Analysis
[horizontal]
URL Permalinking Scheme:: Strict semantic anchor fragments: `#method.new`, `#impl-Send-for-Mutex%3CT%3E`.
Overload Handling:: Rust lacks function overloading; instead, methods with variant behaviors are disambiguated by naming conventions (`new`, `const_new`, `lock`, `blocking_lock`, `try_lock`).
Lifetime & Generic Granularity:: Lifetimes (`'a`, `'_`) and generic trait bounds (`T: ?Sized`) are independently syntax-highlighted and linked.
Inline vs Linked Types:: Every type token in a return signature (`MutexGuard<'_, T>`) links directly to that struct's documentation page.

== 2. Hierarchy Expression

=== Multi-Tier Structural Mapping
Rustdoc uses **collapsible implementation blocks** with **left-aligned rail lines**:

[cols="1,2,2", options="header"]
|===
| Level Transition | Visual Mechanism | Design Tokens Involved
| Crate -> Module | Crate index (`tokio`) -> Module page (`tokio::sync`). | Breadcrumb bar + Left sidebar module list
| Module -> Type Definition | Main heading (`struct Mutex<T>`) + Declaration block with `pub struct Mutex<T> { ... }`. | `h1.main-heading`, `--font-family-code`
| Type -> Implementation Block | `<h2 id="implementations">` heading with collapsible `<details class="toggle implementors-toggle" open>`. | `.implementors-toggle`, `.code-header`
| Impl Block -> Method Item | Nested `<details class="toggle method-toggle" open>` with 24px left indent (`.docblock`). | `--docblock-indent: 24px`
|===

=== Spatial & Navigational Encodings
* *Left Sidebar*: Shows the active module tree (`tokio::sync`) and direct jump links to all sections on the current page (`Implementations`, `Trait Implementations`, `Auto Trait Implementations`, `Blanket Implementations`).
* *Collapsible `<details>` on Every Method*: Every single method can be collapsed individually using a tiny toggle caret, or all methods can be collapsed simultaneously using the global `[+] / [-]` keyboard shortcut.
* *Direct Source Code Jumping*: Every method header features a right-aligned `Source` hyperlink pointing directly to the exact lines in `src/tokio/sync/mutex.rs.html#434-466`.

== 3. Within-Level Differentiation

=== Sibling Entity Disambiguation
Within a module index (`tokio::sync` index):

[horizontal]
Grouping Strategy:: **Type-Kind Grouping**: Modules, Structs, Enums, Traits, Functions, Type Aliases, and Constants are separated into dedicated categorized tables.
Kind Identifiers::
* Distinct color-coded anchor links: Structs render in steel blue (`.struct`), Traits in teal (`.trait`), Macros in green (`.macro`).
* Monospace type declarations with keyword prefixes (`pub async fn`, `pub const fn`, `pub struct`).
Typographic Treatment::
* Symbol names in tables are displayed in bold monospace on the left; summary documentation sentences are in serif prose on the right.

[cols="1,1,2,2", options="header"]
|===
| Symbol Kind | Icon / Glyph | Badge Style / Color | Visual Distinction Mechanism
| Struct | None | `.struct` link color (#2b82c7) | Grouped under `Structs` heading
| Trait | None | `.trait` link color (#2dbfb8) | Grouped under `Traits` heading
| Function | None | Plain function syntax | Has parameter parentheses + return arrow
| Method (Async) | `async` keyword | Tagged in code header | Signature starts with `pub async fn`
| Method (Const) | `const` keyword | Tagged in code header | Signature starts with `pub const fn`

== 4. Detail Layout (Symbol Anatomy)

=== Single Symbol Information Architecture
Order of elements within every method block in Rustdoc:
1. **Collapsible Caret (`[-]`)**: HTML `<summary>` toggle allowing users to collapse the docblock.
2. **Right-Aligned Source Link**: `Source` link pointing to GitHub / HTML source.
3. **Full Typed Signature**: `pub async fn lock(&self) -> MutexGuard<'_, T>`.
4. **Trait Where Clause**: Generic constraints (`where T: Sized`) rendered in an indented sub-block.
5. **Short Description**: Main explanatory paragraphs.
6. **Cancel Safety / Panics / Errors Subheadings**: Standardized warning headings (`Cancel safety`, `Panics`, `Errors`).
7. **Doctest Examples**: Complete, compilable Rust code snippets showing real usage.

=== Layout Mechanics
[horizontal]
Parameter Representation:: Inline within the code signature; Rustdoc relies on expressive Rust types rather than separate parameter tables.
Collapsible Elements:: **Every method has a fold toggle** (`<details class="toggle method-toggle" open>`). Users can fold docblocks while keeping signatures visible.
Signature Wrapping & Formatting:: Clean syntax highlighting with keywords in bold/color and hyperlinked types.
Source Code Integration:: Generated syntax-highlighted HTML views with click-to-highlight line numbers.

== 5. Interlinking & Navigation

=== Cross-Reference Anatomy
[horizontal]
Type Linking Precision:: **100% AST hyperlinking**: Every type, trait bound, and standard library primitive is a direct link to either local crate docs or `doc.rust-lang.org`.
Blanket & Auto Trait Visibility:: Automatically discovers and links compiler-implemented traits (`Send`, `Sync`, `Unpin`, `RefUnwindSafe`).
Keyboard Shortcuts:: Built-in keyboard navigation:
* `?` opens help modal.
* `s` or `/` focuses search bar.
* `[` and `]` expand or collapse all docblocks on the page.

== Unique Innovations & Failure Modes

=== Standout Design Innovations
* **Compiler-Generated Trait & Blanket Impl Verification**: Rustdoc does not just parse docstrings; the Rust compiler verifies that all trait implementations, auto-traits (`Send`, `Sync`), and blanket impls are completely documented.
* **Native `<details>` Folding per Method**: Users can toggle between "signature scan mode" (all docblocks collapsed) and "deep reading mode" (docblocks open) with a single keystroke (`+` / `-`).
* **Source Serif Typography**: Using a classical serif face for prose creates a high-contrast visual cadence between narrative explanations and monospace code signatures.
* **Keyboard Power-User Controls**: Full keyboard navigation (`?`, `s`, `+`, `-`) built into the default HTML output.

=== Critical Anti-Patterns / Friction Points
* **Vertical Page Length**: Types with many trait implementations (like `tokio::sync::Mutex` or standard library types) generate massive web pages that can require 20+ scrolls to navigate.
* **Lack of Visual Parameter Tables**: Because Rustdoc relies entirely on code signatures, functions with 6+ parameters lack dedicated parameter description rows, forcing developers to scan prose paragraphs to understand argument semantics.

=== Transferable Principles for Future Autodoc Systems
1. *Global Collapse / Expand Toggle*: Provide a keyboard shortcut and UI toggle allowing users to collapse all docblocks to view just signatures, or expand all for full details.
2. *Compiler-Verified Invariants*: Display compiler-derived safety and trait properties (like thread safety, immutability, or async bounds) directly in method badges.
3. *Serif Prose / Monospace Code Contrast*: Consider pairing a characterful serif for narrative docstrings with a crisp monospace for signatures to create clear visual separation between prose and code.
