== 1. Granularity

=== Smallest Unit of Documentation
TypeDoc achieves **micro-level addressability**:
* **Every Member is a Named Anchor**: Constructors, methods, accessors, getters/setters, properties, and even overloaded call signatures have discrete permalink anchors (`#bootstrap`, `#bootstrap-1`, `#entrypoints`).
* **Overload Stacking**: Multiple signatures for a single function are rendered inside `<ul class="tsd-signatures">` where each signature `<li class="tsd-signature">` has its own distinct anchor and copyable permalink icon (`svg#icon-anchor`).
* **Source Line Pinned**: Every member has a dedicated `.tsd-sources` footer declaring `Defined in src/lib/application.ts:277` with a direct commit-pinned GitHub link.

=== Granularity Analysis
[horizontal]
URL Permalinking Scheme:: Dot-path fragment identifiers (`classes/Application.html#bootstrap`).
Overload Handling:: Discrete list items under `<ul class="tsd-signatures">`, each rendering parameter lists, return types, and isolated docstring examples.
Accessor / Getter / Setter Handling:: Grouped under an explicit `Accessors` section; getters and setters are visually paired with badge pills.
Modifier Visibility:: Modifiers (`static`, `readonly`, `private`, `protected`, `abstract`) are rendered as prominent pill tags (`<code class="tsd-tag">Static</code>`).

== 2. Hierarchy Expression

=== Multi-Tier Structural Mapping
TypeDoc represents AST inheritance hierarchies both visually and structurally:

[cols="1,2,2", options="header"]
|===
| Level Transition | Visual Mechanism | Design Tokens Involved
| Project -> Module | Top-level breadcrumb navigation + Left sidebar hierarchical tree. | `ul.tsd-breadcrumb`, `--color-ts-module`
| Class -> Inheritance Chain | Interactive nested tree (`section.tsd-panel.tsd-hierarchy`). | `ul.tsd-hierarchy`, `.tsd-hierarchy-item`
| Class -> Member Sections | Grouped into accordion sections (`Index`, `Constructors`, `Properties`, `Methods`, `Accessors`). | `details.tsd-accordion`, `.tsd-index-heading`
| Member -> Parameters | Nested list (`ul.tsd-parameter-list`) with parameter names, types, and defaults. | `span.tsd-kind-parameter`, `--color-ts-parameter`
|===

=== Spatial & Navigational Encodings
* *The Hierarchy Diagram*: Renders an explicit inheritance chain at the top of every class page (`AbstractComponent<Application> -> Application`), with clickable base classes.
* *Accordion Index Panel*: Every class page opens with a collapsible `<details class="tsd-index-content tsd-accordion" open>` index panel categorizing all members alphabetically before the full documentation stream begins.
* *Right-Side Sticky Outline*: Sticky column tracking active section scroll position.

== 3. Within-Level Differentiation

=== Sibling Entity Disambiguation
TypeDoc provides the **highest level of within-level visual distinction** of any system:

[horizontal]
Grouping Strategy:: Hard-categorized into distinct sections: `Constructors`, `Properties`, `Accessors`, `Methods`, `Events`.
Kind Identifiers::
* **Numbered SVG Icon Badges**: Each symbol kind is assigned an SVG icon with a unique color token (`icon-262144` for accessors, `icon-class`, `icon-method`, `icon-property`).
* **Modifier Tags**: Rounded badge pills (`<code class="tsd-tag">Static</code>`, `<code class="tsd-tag">Readonly</code>`, `<code class="tsd-tag">Inherited</code>`).
Typographic Treatment::
* Parameter names in `.tsd-kind-parameter` use distinct styling.
* Function names in `.tsd-kind-call-signature` use monospace font.
* Types are colored using `--color-ts-interface` or `--color-ts-class`.

[cols="1,1,2,2", options="header"]
|===
| Symbol Kind | Icon / Glyph | Badge Style / Color | Visual Distinction Mechanism
| Class | Amber class glyph | `--color-ts-class` | Heading prefix `Class Application` + hierarchy panel
| Method | Indigo method glyph | `--color-ts-method` | Signature parentheses + return arrow + code block
| Accessor | Teal accessor glyph | Tag `<code class="tsd-tag">Accessor</code>` | Getter/setter property syntax
| Static Member | Tag pill | `<code class="tsd-tag">Static</code>` | Tag prepended before member name
| Inherited Member | Muted glyph | `<span class="tsd-is-inherited">` | Tagged with `Inherited from BaseClass`
|===

== 4. Detail Layout (Symbol Anatomy)

=== Single Symbol Information Architecture
Order of elements within every documented member card (`section.tsd-panel.tsd-member`):
1. **Header Anchor Line**: Modifier tag (`Static`) + Member Name + Anchor permalink button.
2. **Signature Line**: Syntax-colored code signature with multi-line indentation for parameters and return types.
3. **Short Description**: Main docstring paragraph.
4. **Parameters List**: `<div class="tsd-parameters">` with `<ul class="tsd-parameter-list">` detailing parameter names, types, optionality markers (`?:`), default values, and parameter-specific comments.
5. **Returns Title & Type**: `<h4 class="tsd-returns-title">Returns Promise<Application></h4>`.
6. **Code Example Block**: Fenced TS code block with a one-click "Copy" button.
7. **Source Code Link**: Footer line declaring `Defined in src/lib/application.ts:277` linking directly to GitHub.

=== Layout Mechanics
[horizontal]
Parameter Representation:: Structured parameter list (`ul.tsd-parameter-list`) with parameter names in bold, types as clickable links, and default values (`= {}`).
Collapsible Elements:: Index panel uses `<details>` accordion; large code blocks feature copy buttons.
Signature Wrapping & Formatting:: Explicit `<br/>` tags and `&nbsp;&nbsp;&nbsp;&nbsp;` indentation in HTML signatures to guarantee readable multi-line parameter formatting.
Source Code Integration:: External commit-pinned GitHub link with line numbers.

== Unique Innovations & Failure Modes

=== Standout Design Innovations
* **Granular Semantic Color Coding**: Unique, distinct color variables for every TypeScript symbol kind (`--color-ts-class`, `--color-ts-interface`, `--color-ts-method`, `--color-ts-property`).
* **Visual AST Inheritance Diagrams**: Inline structural hierarchy panel showing ancestor and descendant classes without leaving the page.
* **Upfront Member Index Accordion**: Solves the "table of contents" problem by placing an expandable index of all class members directly at the top of the class page.
* **Explicit Static/Readonly/Inherited Tags**: Clean visual pills immediately communicate modifier status without requiring users to inspect syntax.

=== Critical Anti-Patterns / Friction Points
* **Visual Clutter**: The sheer density of icons, tags, colored types, and horizontal rules can feel overwhelming for developers seeking a quick API overview.
* **Hardcoded Spacing in Signatures**: Injecting `<br/>` and `&nbsp;&nbsp;&nbsp;&nbsp;` directly into HTML DOM for parameter wrapping rather than relying on CSS flexbox/grid makes responsive adaptation on mobile rigid.

=== Transferable Principles for Future Autodoc Systems
1. *The Kind Color Token System*: Assigning a stable, recognizable color palette to symbol kinds (e.g. orange for classes, blue for interfaces, purple for functions) drastically speeds up visual scanning.
2. *The Upfront Member Index*: Every complex class should open with an index panel categorizing its members (Constructors, Properties, Methods, Accessors) before rendering full member bodies.
3. *Explicit Modifier Badging*: Prominently badge modifiers (`static`, `async`, `readonly`, `inherited`) as visual pills next to symbol names.
