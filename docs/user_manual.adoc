This is the comprehensive user manual for *Golem*, a high-performance, Python-native static site generator designed for technical documentation, API portals, and developer guides.

== Overview

Golem is designed to make writing, maintaining, and deploying technical documentation fast, modular, and reliable. Built upon native AsciiDoc parsing and Chameleon cascading HTML5 templates, Golem combines high compilation performance with deep extensibility.

=== Key Features

*Incremental DAG Compilation*::
Tracks document dependencies via a Directed Acyclic Graph (DAG) cache (`.golem/cache.json`). Only modified files and pages that include them are recompiled.

*Partial Files Protocol*::
Files prefixed with `_` or stored in `_*/` directories are treated as reusable partials—monitored in the DAG for includes, but excluded from standalone HTML generation and navigation menus.

*Cascading Theme & Static Asset Pipeline*::
Multi-tier static asset resolution with intuitive override precedence (user assets override theme assets).

*Zero-Dependency Live Reload Server*::
Built-in multi-threaded development server with Server-Sent Events (SSE) live reload and in-browser error overlays.

*Extensible Plugin Ecosystem*::
Pluggy-powered plugin lifecycle hooks with automatic discovery across built-in plugins, installed package entry points, and local workspace scripts.

*Precise Compiler Diagnostics*::
Source coordinate formatting (`file:line:col`) with context lines and visual error pointers.

== Project Configuration

Golem projects are configured either through a dedicated `golem.toml` file in the project root or within `pyproject.toml` under the `[tool.golem]` namespace.

=== Configuration Resolution

When Golem runs, it discovers configuration files in the following order:

1. An explicit path passed to the `--config <path>` command-line option.
2. `golem.toml` in the current working directory.
3. `pyproject.toml` containing a `[tool.golem]` table in the current working directory.

=== Configuration Schema

==== `[site]` Table

Global site metadata:

`title` (string, default: `"Golem Docs"`)::
Primary site title displayed in headers and browser page titles.

`author` (string, default: `"Anonymous"`)::
Site author name or organization.

`site_url` (string, optional)::
Canonical public base URL of the site (e.g. `https://example.com/docs/`).


==== `[build]` Table

Compilation paths and build settings:

`content_dir` (string, default: `"content"`, or `"docs"` in packages)::
Source directory containing AsciiDoc documentation files.

`output_dir` (string, default: `"dist"`)::
Destination directory for generated HTML and static assets.

`theme` (string, default: `"default"`)::
Name of the active layout theme.

`static_dir` (string, default: `"static"`, or `"docs/static"`)::
Directory containing user static assets to copy into `dist/static/`.

`templates_dir` (string, default: `"templates"`)::
Directory containing custom Chameleon page layout templates.

`plugins_dir` (string, default: `"plugins"`)::
Directory containing local Python plugin modules.

`strict` (boolean, default: `false`)::
When enabled (`true`), fails compilation immediately on any syntax error or parse warning.


==== `[navigation]` Table

Site navigation hierarchy and sidebar order:

`nav` (list of strings or mappings, optional)::
Explicit list order of document paths defining the sidebar navigation tree (e.g. `nav = ["index.adoc", "getting-started.adoc", "api/reference.adoc"]`). If omitted, Golem automatically discovers and orders files from disk.


==== `[plugins]` Table

Plugin activation:

`plugins` (list of strings, default: `["golem.plugins.doctest", "golem.plugins.apidoc"]`)::
List format specifying enabled plugin module identifiers, entry points, or local script names.


=== Configuration Examples

==== Standalone `golem.toml`

[source,toml]
----
[site]
title = "Acme Developer Portal"
author = "Acme Documentation Team"
site_url = "https://docs.acme.example.com"

[build]
content_dir = "content"
output_dir = "dist"
theme = "default"
static_dir = "static"
templates_dir = "templates"
plugins_dir = "plugins"
strict = false

[navigation]
nav = [
    "index.adoc",
    "getting-started.adoc",
    "architecture/overview.adoc",
    "api/reference.adoc",
]

[plugins]
plugins = [
    "golem.plugins.doctest",
    "golem.plugins.apidoc",
]
----

[source,toml]
----

[tool.golem.navigation]

    "index.adoc",
    "user_manual.adoc",
    "developer_guide.adoc",
]

[tool.golem.plugins]

    "golem.plugins.doctest",
    "golem.plugins.apidoc",
]
----

== Partial Files Protocol (`_*.adoc`)

Golem provides first-class support for modular documentation through its **Partial Files Protocol**.

=== Naming & Structure

Any AsciiDoc file whose filename starts with an underscore (such as `_header.adoc`, `_sidebar.adoc`, `_tip.adoc`) or that resides within an underscore-prefixed directory (such as `_includes/`, `_partials/`, `content/_snippets/`) is treated as a partial file.

[source,text]
----
content/
├── index.adoc              <-- Standalone page (compiled to dist/index.html)
├── guide.adoc              <-- Standalone page (compiled to dist/guide.html)
├── _sidebar.adoc           <-- Partial file (NOT compiled to standalone HTML)
└── _includes/
    ├── _setup.adoc         <-- Partial file
    └── config.adoc         <-- Partial file (inside underscore directory)
----

=== Partial File Rules

*Excluded from Standalone Output*::
Partial files are never compiled directly into standalone `.html` files in `dist/`.

*Excluded from Navigation*::
Partial files and partial directories are automatically excluded from navigation trees and sidebar menus.

*Tracked in DAG Cache*::
Golem registers SHA-256 hashes and dependencies in `.golem/cache.json`. When a document uses `\include::_header.adoc[]`, Golem links the dependency.

*Recursive Invalidation*::
Modifying or deleting a partial file invalidates all parent documents that include it, triggering automatic recompilation during incremental builds.


== Static Assets Pipeline

Golem provides an integrated asset pipeline that synchronizes CSS, JavaScript, images, fonts, and other binary files to `dist/static/`.

=== Precedence Rules

Static assets are resolved in a cascading hierarchy. If files share identical relative paths, higher-priority sources override lower-priority sources:

1. **Package Theme Defaults** (`src/golem/templates/<theme>/static`): Base CSS styles bundled with Golem.
2. **Local Theme Directory** (`themes/<theme>/static`): Assets provided by a local theme.
3. **Custom Templates Directory** (`templates/static` or `templates_dir/static`).
4. **User Static Directory** (`static/` or configured `static_dir`): Highest priority. User files override theme assets with matching filenames.

=== Referencing Assets

Reference synced static assets in AsciiDoc documents or HTML templates:

[source,html]
----
<link rel="stylesheet" href="/static/css/custom.css">
<img src="/static/images/logo.png" alt="Logo">
----

== Live-Reload Development Server & Error Handling

Golem includes an integrated development server with real-time browser synchronization.

=== Server Architecture

Running `golem serve` launches a local development server:

*Threading HTTP Server*::
Uses Python `http.server.ThreadingHTTPServer` to serve the `dist/` directory concurrently.

*Background Polling Watcher*::
Monitors source files and configuration changes every second.

*Server-Sent Events (SSE)*::
Connected browser tabs listen for reload events on `/golem-reload`.

*Automatic Script Injection*::
The server injects the SSE client listener into served HTML pages on-the-fly.

----

  |   Browser   |            |  LiveReloadServer  |            | BuildEngine |
  +------+------+            +---------+----------+            +------+------+

         |                             |                              |

         |  3. Serve HTML              |                              |

         |                             |                              |
         |  4. Open EventSource        |                              |
         |     Conn: /golem-reload     |                              |
         +---------------------------->+                              |
         |                             |                              |
         |                             |  5. Poll files for changes   |

         |                             |            |                 |
         |                             |<-----------+                 |
         |                             |                              |

         |                             +----------------------------->+

=== In-Browser Diagnostic Overlay

The development server is built to be resilient against authoring errors:

*Non-Crashing Error Handling*::
AsciiDoc syntax errors or missing includes do not terminate the `golem serve` process.

*In-Browser `#golem-error-overlay`*::
Syntax errors and compiler warnings are displayed as an overlay banner at the top of the browser viewport with file coordinates and error details.

*Instant Recovery*::
When you fix the error and save the source file, Golem recompiles the page, dismisses the overlay, and refreshes the browser automatically.


== Incremental DAG Caching

Golem tracks compilation dependencies using a JSON DAG cache in `.golem/cache.json`.

*SHA-256 Hashing*::
Caches content hashes to avoid redundant compilation of unchanged documents.

*In-Memory MTime Cache*::
Accelerates hash checks using file size and modification timestamps.

*Atomic Cache Writes*::
Uses atomic temporary file swapping with advisory file locking (`fcntl.flock`) to prevent corruption.

*Recursive Deletion Tracking*::
Detects deleted includes and purges stale nodes while invalidating parent pages.

*Global Asset Monitoring*::
Changes to `golem.toml`, `pyproject.toml`, or `themes/<theme>/skeleton.pt` trigger full site rebuilds.


== CLI Command Reference

=== `golem init`

Initialize a new Golem project and configuration.

[source,bash]
----
golem init [--template <type>] [--output-dir <dir>] [-C <dir>]
----

`--template <type>` (default: `package`)::
Project template profile (`package`, `site`, `book`, or `simple`).

`--output-dir <dir>`::
Optional output directory override.

`-C`, `--directory <dir>`::
Change working directory before executing.


=== `golem new`

Create a new AsciiDoc document skeleton with structured frontmatter metadata.

[source,bash]
----
golem new <type> <name> [-C <dir>]
----

`<type>` (required)::
Document classification type (e.g. `guide`, `post`, `rfc`, `api`).

`<name>` (required)::
Document title; automatically converted into a kebab-case slug filename.

`-C`, `--directory <dir>`::
Change working directory before executing.


=== `golem build`

Run the incremental compiler and generate static HTML pages.

[source,bash]
----
golem build [--config <path>] [--clean] [--strict] [-v|--verbose] [-C <dir>]
----

`--config <path>` (default: `golem.toml`)::
Path to configuration file.

`--clean`::
Empty output directory (`dist/`) and clear cache before building.

`--strict`::
Abort compilation with non-zero exit code on any warning or syntax error.

`-v`, `--verbose`::
Enable verbose debug logging output.

`-C`, `--directory <dir>`::
Change working directory before executing.


=== `golem serve`

Start the local development server with SSE live reloading and in-browser error overlays.

[source,bash]
----
golem serve [--port <port>] [--host <host>] [--strict] [-C <dir>]
----

`--port <port>` (default: `8000`)::
Local HTTP port.

`--host <host>` (default: `127.0.0.1`)::
Network binding host address.

`--strict`::
Enforce strict validation during live-reloading.

`-C`, `--directory <dir>`::
Change working directory before executing.


=== `golem plugins`

Inspect installed, configured, and local plugins.

[source,bash]
----
golem plugins [--json] [-C <dir>]
----

`--json`::
Output plugin list in structured JSON format.

`-C`, `--directory <dir>`::
Change working directory before executing.


=== `golem themes`

Inspect the active theme and list all available themes.

[source,bash]
----
golem themes [--json] [-C <dir>]
----

`--json`::
Output theme list in structured JSON format.

`-C`, `--directory <dir>`::
Change working directory before executing.

`file:line:col` or `file:line`

----

   |     ^-- Unclosed attribute list

== Plugin Development

Golem supports lifecycle hooks via Pluggy for AST transformations, content pre-processing, HTML post-processing, and CLI commands.

=== Lifecycle Hooks

`on_pre_parse(raw_content: str) -> str`::
Transform raw AsciiDoc content before AST parsing.

`on_post_parse(ast)`::
Inspect or modify the parsed AsciiDoc AST.

`on_post_render(html_content: str) -> str`::
Modify final rendered HTML before saving.

`golem_add_subcommands(cli: click.Group) -> None`::
Register custom subcommands on the Golem CLI.


=== Example Local Plugin

Create a script in `plugins/word_count.py`:

[source,python]
----
import pluggy

hookimpl = pluggy.HookimplMarker("golem")

@hookimpl
def on_post_render(html_content: str) -> str:
    count = len(html_content.split())
    return f"<!-- Total words: {count} -->\n" + html_content
----
