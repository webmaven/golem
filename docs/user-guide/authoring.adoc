=== 2. Source Code, Listing Headers & Callouts
Golem provides rich, IDE-style code listings with semantic header bars, block titles, uppercase language badges, test/state role badges, and one-click clipboard copying.

.hello_golem.py
[source,python]
----
import click <1>

@click.command() <2>
def hello():
    click.echo("Hello, Golem!")
----
<1> Import the click CLI framework.
<2> Decorate the function as a command entry point.

==== Listing Headers, Badges & Clipboard Copying

When authoring code blocks in AsciiDoc:

* *Block Titles & Filenames:* Prefixing a block with `.filename.py` or `.Title` renders a clean, styled `.listing-title` in the top header bar.
* *Language Badges:* Specifying `[source,python]` or `[source,toml]` automatically displays a capitalized language badge (e.g. `PYTHON`, `TOML`, `ASCIIDOC`) via `.badge.badge-lang`.
* *Role Badges:* Specifying `role="test"`, `role="shared"`, or `role="reset"` in block attributes renders distinctive semantic role badges (`.badge-test`, `.badge-shared`, `.badge-reset`) to indicate test isolation or execution state.
* *One-Click Clipboard Copy:* Every listing header includes an accessible copy button (`.listing-copy-btn`). Clicking the button copies the listing's code directly to the user's clipboard and displays a visual confirmation checkmark.

== Multi-View Derived Renderings

Technical documentation often needs to demonstrate not just raw AsciiDoc source code, but also how that source is parsed, compiled, or visually rendered. Golem includes a built-in *Multi-View Derived Rendering Engine* that compiles code snippets into interactive tabbed containers at build time.

=== The `render` Attribute & Aliases

To generate derived multi-view tabs, author a `[source,asciidoc]` block and specify the `render` attribute (or one of its aliases: `views`, `display`, `formats`):

.Multi-View Syntax Example
[source,asciidoc]
----
.Interactive Admonition Demo
[source,asciidoc,render="source,asg,html,preview"]
----
[NOTE]
====
This note is rendered into AsciiDoc, ASG JSON, HTML, and Live Preview tabs!
====
----
----

=== Supported View Channels

Golem supports four canonical compilation view channels:

[cols="1,1,3"]
|===
| View Channel | Aliases | Description

| `source`
| `asciidoc`, `adoc`, `src`
| The raw, syntax-highlighted AsciiDoc input snippet (Tab label: *AsciiDoc*).

| `asg`
| `ast`, `json`
| The parsed Abstract Semantic Graph (ASG) dictionary serialized as formatted, syntax-highlighted JSON (Tab label: *ASG*).

| `html`
| `rendered-html`, `markup`
| The compiled HTML5 fragment source code, syntax-highlighted (Tab label: *HTML*).

| `preview`
| `live`, `rendered`, `view`
| The live, interactive HTML component rendered directly inside a `.rendered-preview` container (Tab label: *Preview*).
|===

=== Zero-JS Baseline & Progressive Enhancement

Golem's multi-view tab system is engineered with progressive enhancement and accessibility:

* *Zero-JS Baseline:* When JavaScript is unavailable or disabled, the first tab is active and visible by default, while subsequent tab panes are hidden using standard HTML `hidden` attributes. All content is fully indexed by search engines and readable in text browsers.
* *Interactive Tab Switching:* With JavaScript enabled, clicking any tab button or navigating via keyboard arrows (`role="tab"`, `role="tablist"`, `role="tabpanel"`) toggles the visible pane with seamless transitions.
* *Context-Aware Clipboard Copying:* When viewing a multi-view container, the clipboard copy button automatically targets the code or text of whichever tab is currently active (e.g. copying JSON when the ASG tab is selected, or raw HTML when the HTML tab is selected).

== Partial Files Protocol (`_*.adoc`)

In large technical books and manuals, chapters are often split across reusable sub-units included into parent documents via `include::path.adoc[]`.

[IMPORTANT]
====
Any file prefixed with an underscore (e.g. `_header.adoc`, `_sidebar_notes.adoc`, `_footer.adoc`) is treated as a *Partial File*.
====

* *No Standalone Compilation:* Partial files are *never compiled into standalone HTML files* in `dist/`.
* *DAG Dependency Tracking:* When a partial file is modified, Golem's incremental DAG compiler traverses `.golem/cache.json` and automatically rebuilds every parent document that includes it.
