= API Reference Generator & Inline Macro
:nav_order: 30
:idprefix:
:idseparator: -
:sectanchors:
:source-highlighter: highlight.js

Golem includes a built-in API reference documentation generator plugin (`golem.plugins.apidoc`) that inspects Python source modules, extracts type annotations and docstrings, and renders standard AsciiDoc API documentation.

== 1. Generating API Reference Pages (`golem apidoc`)

You can generate comprehensive API reference pages for your Python packages either automatically during build or via the CLI:

.Terminal
[source,bash]
----
golem apidoc [PACKAGE] [--output <dir>] [--docstring-style <style>]
----

=== Configuration via `golem.toml` or `pyproject.toml`

Configure API generation settings in your project configuration:

.golem.toml
[source,toml]
----
[api]
packages = ["my_package", "my_package.core"]
output_dir = "api"
docstring_style = "auto" # Options: "auto", "google", "numpy", "sphinx", "asciidoc"
----

During builds or CI/CD pipelines, Golem reads this configuration and generates hierarchical reference pages under `content_dir/api/` matching your package structure.

== 2. Inline Block Macro: `golem:apidoc`

In technical manuals, guides, or tutorials, you often want to splice live API documentation for a specific class or function directly into your narrative prose.

Golem provides the `golem:apidoc[...]` inline block macro:

.engine_guide.adoc
[source,asciidoc]
----
= Engine Architecture Guide

Here is the specification for the primary BuildEngine class:

golem:apidoc[target="golem.engine.BuildEngine", depth="all"]
----

=== Macro Parameters

[cols="1,1,3"]
|===
| Parameter | Default | Description

| `target`
| *(Required)*
| Full Python import path of the target module, class, method, or function (e.g. `"golem.config.GolemConfig"`). Can also be passed as the first positional argument.

| `depth`
| `"all"`
| Introspection depth: `"all"` (full class with all methods and attributes), `"methods"` (methods only), `"summary"` (class signature and overview docstring).

| `style`
| `"auto"`
| Docstring parsing format (`"auto"`, `"google"`, `"numpy"`, `"sphinx"`, `"asciidoc"`).
| `heading_level_offset`
| `0`
| Integer offset applied to all headings in the generated API documentation. Useful when the macro appears inside a section (e.g. `offset=1` ensures generated `== Headings` become `=== Headings` to match the embedding depth).
|===

=== Macro Processing — ASG Splice (Primary Path)

When Golem processes documents containing `golem:apidoc[...]` macros, the primary expansion path runs via the `on_asg_created` plugin hook after full semantic resolution of the document:

1. The `on_asg_created` hook receives the fully resolved ASG dictionary for the document.
2. `_splice_blocks()` recursively traverses the ASG block tree.
3. For each block-macro node or paragraph whose text contains an unescaped `golem:apidoc[...]` call:
   .. `AsciiDocApi.get_asg_nodes()` resolves the Python target on `sys.path`, renders it to AsciiDoc markup using `asciidocstring`, then parses and resolves the markup to return ASG block dictionaries.
   .. The macro node is replaced in-place by the returned block list.
4. Verbatim blocks (`listing`, `literal`, `verse`) and backtick-escaped inline code are never expanded.
5. Backslash-escaped macros (`\golem:apidoc[...]`) are unescaped to literal text without triggering expansion.
6. If the target cannot be resolved, a `[WARNING]` admonition block is inserted so the failure is visible in rendered output.

[NOTE]
====
The `on_pre_parse` text-substitution hook is retained as a *deprecated fallback* for pipelines that do not reach `on_asg_created`. When triggered it emits a `logger.warning` message: _"on_pre_parse macro expansion is deprecated; use on_asg_created"_. It will be removed in a future release.
====
