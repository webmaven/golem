== 1. Directory Structure

A standard Golem project follows this file-system layout:

[source,text]
----
my-docs-project/
├── golem.toml          # Primary site configuration
├── content/            # Directory containing .adoc source files
│   ├── index.adoc      # Primary homepage entry point
│   ├── intro.adoc
│   └── reference/
│       └── advanced.adoc
├── plugins/            # Local/Project-specific Python plugins
│   └── my_macro.py
├── themes/             # Local theme overrides
│   └── custom-theme/
│       ├── skeleton.pt # Chameleon TAL template
│       └── theme.css   # Custom CSS property overrides
└── static/             # Static assets (images, WebGPU assets, custom JS)
    └── logo.png
----

During build, Golem outputs to a distribution directory (default: `dist/`) and manages state inside a hidden directory:

[source,text]
----
my-docs-project/
├── dist/              # Compiled HTML/CSS/JS output
└── .golem/             # Caching, hashes, and incremental compile state
    └── cache.json      # Maps file paths to SHA-256 hashes & inclusion edges
----

== 2. Project Configuration (`golem.toml`)

Golem uses TOML for project configuration. Alternatively, for Python software projects, configuration can be embedded inside `pyproject.toml` under the `[tool.golem]` section.

=== 2.1 Configuration Schema

[source,toml]
----
[site]
name = "Golem Project Documentation"
url = "https://example.com/docs"
author = "Michael Bernstein"
default_language = "en"

[build]
content_dir = "content"
output_dir = "dist"
theme = "default"         # Built-in, or absolute/relative path to local theme
clean = true              # Empty output directory before building
toc_levels = 3            # TOC depth (1 to 6)
plugins_dir = "plugins"   # Directory of local project-specific plugins
quiet = false             # Suppress non-error output
strict = false            # Treat warnings as fatal errors

[navigation]
mode = "auto"             # Modes: "auto", "manual", "hybrid"
# Explicit navigation tree mapping (used in manual or hybrid mode)
nav = [
    { title = "Getting Started", path = "intro.adoc" },
    { title = "Core Concepts", path = "concepts/index.adoc" },
    { title = "Advanced Guide", path = "reference/advanced.adoc" }
]

[plugins]
# List of packaged pluggy plugin names to load via entry points
enabled = [
    "golem_plugin_diagrams"
]

[api]
# Python packages to automatically scan and build /api/ reference guides for
packages = [
    "golem"
]
output_dir = "api"
docstring_style = "google"  # "google", "numpy", or "plain"
----

=== 2.2 Configuration Resolution
When Golem compiles, it merges configurations in this order of precedence (highest to lowest):

1.  Command-line arguments (e.g. `--output-dir dist`).
2.  `golem.toml` (or `[tool.golem]` in `pyproject.toml`).
3.  Golem internal package defaults.

== 3. Navigation & Site Map Resolution Rules

Golem compiles a unified hierarchical site navigation tree from source files using a three-tier prioritisation strategy.

=== 3.1 Tier 1: Idiomatic Include-Tree (The Inclusion DAG)
In highly technical documentation, the primary site structure is often defined inside a root file (like `index.adoc` or `book.adoc`) using standard AsciiDoc includes:

[source,asciidoc]
----
= Golem Documentation
:toc:

\include::01-introduction.adoc[]
\include::02-architecture.adoc[]
----

When Golem parses the root document, it tracks the inclusion tree. If `navigation.mode` is set to `"auto"` (or `"hybrid"`) and an inclusion tree is found in the entry document, Golem resolves this structural tree directly as the hierarchical table-of-contents navigation for the entire site.

=== 3.2 Tier 2: Explicit TOML Mapping
When `navigation.mode` is `"manual"`, Golem ignores filesystem hierarchies and inclusion structures, building the left-hand navigation sidebar strictly from the order defined in the `nav` list of `golem.toml`:

[source,toml]
----
nav = [
    { title = "Welcome", path = "index.adoc" },
    { title = "Architecture", path = "concepts/architecture.adoc" }
]
----

=== 3.3 Tier 3: Filesystem Auto-Discovery (The Fallback)
If no inclusion tree is defined in the root document and no manual `nav` array is present in the configuration, Golem falls back to traversing the `content/` directory recursively:

1.  **Sorting Order:** Subfolders and files are sorted. If prefixes like `01-`, `02-` are found, Golem strips the prefix from the user-facing title but preserves the numerical sorting order (e.g., `01-getting-started` is displayed as "Getting Started" but sorted first).
2.  **Homepages:** Any file named `index.adoc` or `README.adoc` inside a folder is designated as the parent homepage of that folder node.

== 4. The Golem AST/ASG Build Pipeline

Golem translates raw source text into responsive static pages through a deterministic compilation lifecycle.

[source,mermaid]
....
flowchart TD
    A[Raw AsciiDoc File] -->|1. Parse & Native Include Preprocess| B[Syntax-level AST]
    B -->|2. AST Transformations| C[Normalized AST]
    C -->|3. ASG Resolver| D[Resolved ASG]
    D -->|4. HTML Rendering & Template Assembly| E[Final Static HTML Page]
....

=== 4.1 Phase 1: Native Include Preprocessing & Lark Parsing
*   **Action:** Executes `asciidoctrine.parse_to_ast(source, base_dir)`.
*   **Include-Tree Tracking:** Since `asciidoctrine` natively includes nested files, Golem bypasses manual file scanning. After Lark completes parsing, Golem extracts `ast.included_files` (pre-sorted absolute paths populated by the preprocessor) to establish inclusion edges in Golem's dependency DAG.
*   **Plugin Hooks:** Triggers `on_pre_parse(raw_content: str) -> str` to allow text-level replacements before parsing (such as custom preprocessor macros).

=== 4.2 Phase 2: Lark Syntax Parsing & Error Interception
*   **Output:** Returns a `Document` object (subclass of `BlockNode`), representing the syntax-level AST.
*   **Diagnostics & Compiler Error Interception:**
    If a document contains syntactically invalid AsciiDoc structures, the Lark engine raises a structured `AsciiDocSyntaxError` containing exact coordinates (`line`, `column`) and a visual caret string (`context`). Golem catches this exception:
    1. **CLI Mode:** Prints a formatted terminal warning displaying the filename, coordinates, and highlighted caret preview, and exits with a non-zero code.
    2. **Serve Mode:** Emits a JSON-structured payload over the Server-Sent Events (SSE) socket. The browser client catches the payload and renders a temporary high-contrast dark overlay with the visual caret to allow instantaneous, seamless DX correction without crashing the background thread.

=== 4.3 Phase 3: AST Normalization Transformations
*   **Action:** Executes Golem-specific AST transformers subclassing `asciidoctrine.nodes.NodeTransformer`.
*   **Tasks:** Translates custom Golem inline and block macros.
*   **Plugin Hooks:** Triggers `on_ast_created(ast: Document) -> Document`.

=== 4.4 Phase 4: Semantic Resolution (ASG Generation)
*   **Action:** Resolves variables, attributes, conditionals, and outline structures.
*   **Implementation:** Calls `asciidoctrine.resolver.ASGResolver(ast).resolve(ast)`. This filters out comment nodes and substitutes attribute variables (e.g. `{site-name}`) with their values.
*   **Plugin Hooks:** Triggers `on_asg_created(asg: dict) -> dict` (operating on the resolved ASG dictionary structure returned by the resolver).

=== 4.5 Phase 5: HTML Rendering & Template Layout Assembly
*   **Action:** Combines fine-grained recursive translation and layout framing:
    1. **Recursive HTML Translation (`HtmlRenderer`):** Since recursive document node structures (such as lists nested inside sidebars or inline formatting) are complex and inefficient to map in HTML template files, Golem's pure-Python walker traverses the ASG and compiles the recursive document body into a clean, flat HTML content segment.
    2. **Layout Framing (Chameleon):** The compiled HTML content segment is passed to Golem's Chameleon templates along with resolved ASG attributes, sidebar navigation maps, and the active TOC tree. Chameleon TAL integrates these variables into the main layout slots using standard structure assignment.
*   **Plugin Hooks:** Triggers `on_post_render(html_content: str) -> str` on the final compiled page.
*   **Output:** Writes the optimized HTML file to the target output directory.

== 5. Incremental Build Caching (The Dependency DAG)

To support instant, sub-100ms hot-reloads on massive technical documents, Golem manages an incremental dependency cache tracked as a Directed Acyclic Graph (DAG) stored inside `.golem/cache.json`.

=== 5.1 Cache State Schema
The cache state tracks document hashes and inclusion dependencies:

[source,json]
----
{
  "version": "1.0",
  "files": {
    "content/index.adoc": {
      "hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "dependencies": ["content/intro.adoc", "content/reference/advanced.adoc"]
    },
    "content/intro.adoc": {
      "hash": "8c7365213e3f3604f56f4d1e2e1e2439ba579124",
      "dependencies": []
    },
    "content/reference/advanced.adoc": {
      "hash": "24e2ba7e1082c9f53e1e2e1e2439ba579124",
      "dependencies": []
    }
  }
}
----

=== 5.2 Compilation and Cache Invalidation Protocol
Every compilation run executes this sequence:

1.  **Scan Phase:** Golem traverses the `content/` directory and computes the SHA-256 hash of each `.adoc` file.
2.  **Invalidation Check:**
    *   If the file's computed hash _matches_ the hash in the cache, and none of its dependencies have changed, its parsed AST is pulled directly from `.golem/` cache files, bypassing Lark parser execution.
    *   If a file's hash _differs_, it is scheduled for compilation.
    *   **Recursive Invalidation:** If a file `B.adoc` is modified, Golem traverses the dependency DAG upwards, invalidating and scheduling every parent file that includes `B.adoc`.
    *   **Template Invalidation:** Changes to master layout templates (`skeleton.pt`, `page.pt`, `layout.pt`) or configuration trigger a full site rebuild. Granular component templates only invalidate documents containing matching ASG node types (discovered via `collect_node_types()`).
    *   **Plugin Invalidation Hooks:** Registered plugins implementing `golem_mark_stale` can evaluate changed files and cache metadata to mark additional dependent files for recompilation.
3.  **Compilation Execution:** Only scheduled files undergo the parsing, transformation, and resolution pipeline.
4.  **Save State:** The updated hashes and inclusion dependencies are persisted back to `.golem/cache.json` using atomic temporary file replacement protected by cross-process file locks (`filelock.FileLock`).

== 6. Pluggy-Based Plugin System

Golem's extensibility is driven by `pluggy`, the industry-standard plugin management framework.

=== 6.1 Hook Specifications
All plugins hook into the core pipeline by implementing one or more of these hooks defined in `golem/plugins/__init__.py`:

[source,python]
----
import pluggy
import click
from pathlib import Path
from typing import Any
from asciidoctrine.nodes import Document

hookspec = pluggy.HookspecMarker("golem")
hookimpl = pluggy.HookimplMarker("golem")

class GolemSpecs:
    @hookspec
    def on_pre_parse(self, raw_content: str) -> str:
        """
        Invoked before the source is parsed by Lark.
        Allows global text-level replacements (e.g. custom macro expansion).
        """

    @hookspec
    def on_ast_created(self, ast: Document) -> Document:
        """
        Invoked immediately after Lark parser transforms the document.
        Allows mutating the syntax-level AST nodes before semantic resolution.
        """

    @hookspec
    def on_asg_created(self, asg: dict) -> dict:
        """
        Invoked after the ASGResolver compiles the AST to a resolved dictionary.
        Allows mutating variables, outlines, and structural layout parameters.
        """

    @hookspec
    def on_post_render(self, html_content: str) -> str:
        """
        Invoked after Chameleon integrates the content into the template.
        Allows rewriting generated HTML (e.g. injecting Pygments class names).
        """

    @hookspec
    def golem_add_subcommands(self, cli: click.Group) -> None:
        """
        Invoked during Click CLI bootstrap.
        Allows plugins to register custom CLI subcommands (e.g. `doctest`, `apidoc`).
        """

    @hookspec
    def golem_mark_stale(
        self,
        changed_files: list[Path],
        cache_metadata: dict[str, dict[str, Any]],
    ) -> list[Path] | None:
        """
        Invoked during incremental build dependency resolution.
        Allows plugins to analyze changes and flag additional pages as stale.
        """
----

=== 6.2 Hybrid Discovery Model

Golem automatically initializes both packaged and project-specific plugins:

1.  **Project-Specific Local Plugins:**
    *   During initialization, Golem appends the `plugins_dir` (default: `plugins/`) in the project root to `sys.path`.
    *   It scans the directory for Python files (e.g. `plugins/my_macro.py`).
    *   It imports them using `importlib.import_module` and registers them with the `pluggy` manager.
2.  **Packaged Plugins:**
    *   Golem uses `importlib.metadata.entry_points(group="golem.plugins")` to locate installed PyPI packages registering Golem hooks.
    *   It loads and registers enabled packages specified inside `golem.toml`.

== 7. Programmatic API Reference & Docstring Extraction

Golem blends hand-written prose with autogenerated module, class, and method references.

=== 7.1 Static Extraction via `griffe` and `asciidocstring`
Golem implements a dedicated extractor (`golem/plugins/apidoc/core/`) to generate API reference modules:

1.  Golem creates a `griffe.GriffeLoader` (via `create_griffe_loader()` in `extractor.py`), configured with the project's search paths and docstring style.
2.  It calls `loader.load_module("package_name")` to obtain a `griffe.Module` object representing the package's full object tree.
3.  It walks the returned tree recursively, classifying members into `griffe.Module`, `griffe.Class`, `griffe.Function`, and `griffe.Attribute` nodes.
4.  For each object, the formatter (`formatter.py`) renders signatures (via `format_parameters()` and `format_function_signature()`) and docstrings into AsciiDoc markup.
5.  Golem compiles these into standard, hyperlinked AsciiDoc reference subpages saved inside the configured `[api] output_dir` (default: `content/api/`).

=== 7.2 Inline Block Macro: `golem:apidoc`
To splice API references directly into technical books or guides, Golem implements a custom block macro:

[source,asciidoc]
----
golem:apidoc[target="golem.engine.BuildEngine", depth="methods"]
----

The macro is implemented via the `on_pre_parse` hook in `golem/plugins/apidoc/__init__.py`.
Before the document is parsed by Lark, the plugin performs a regex search over the raw
AsciiDoc source for `golem:apidoc[...]` occurrences, resolves the target symbol via
`AsciiDocApi.render_symbol()`, and replaces the macro text with the rendered AsciiDoc
fragment in-place. The patched source is then passed to the standard parse pipeline.

NOTE: This text-substitution approach means injected content is re-parsed in the context
of the outer document. A deeper AST-level implementation (splicing pre-built ASG nodes
via a `NodeTransformer` after parsing) is tracked in
https://github.com/webmaven/golem/issues/10[GitHub issue #10].

== 8. HTML ASG Rendering Engine (`golem/renderer.py`)

Golem's `HtmlRenderer` translates `asciidoctrine` ASG structures directly into HTML5. Since the resolved ASG returned by `ASGResolver().resolve()` is structured as a nested Python dictionary representation of the AST nodes, Golem's renderer implements a robust recursive dictionary walker that mirrors `NodeVisitor`.

=== 8.1 Node to HTML Tag Mappings

[cols="1,2,2"]
|===
| ASG Node `name` | HTML5 Implementation | Attributes & Classes

| `document` | `<body>` / Wrapper container | `class="golem-doc"`
| `section` | `<section class="golem-section-{level}">` | Generates a slugified `id` from the section title for links
| `title` | `<h1>` to `<h6>` matching level | Matches Section/Block level
| `paragraph` | `<p>` | Standard text container
| `listing` | `<pre><code class="language-{lang}">` | Incorporates Pygments or fallback style variables
| `list` (unordered) | `<ul>` | List element
| `list` (ordered) | `<ol>` | Supports custom marker styles
| `list_item` | `<li>` | Handles paragraph nestings
| `dlist` | `<dl>` (description list) | Maps terms and description nodes
| `dlist_item` | `<div class="golem-dlist-item">` | Wraps terms and details
| `dlist_term` | `<dt>` | Term elements
| `admonition` | `<aside class="golem-admonition {variant}">` | Classes: `.note`, `.tip`, `.important`, `.warning`
| `sidebar` | `<aside class="golem-sidebar">` | Generates floating side-container blocks
| `quote` | `<blockquote class="golem-quote">` | Captures quotation strings
| `table` | `<table class="golem-table">` | Responsive CSS grids
| `row` | `<tr>` | Standard rows
| `cell` | `<td>` / `<th>` | Handles `colspan` and `rowspan` parameters
| `thematic_break` | `<hr class="golem-break">` | Horizontal rule
| `kbd` | `<kbd class="golem-key">` | Wraps single keyboard keys or key strings joined by `+`
| `button` | `<span class="golem-btn">` | Premium styled UI buttons
| `menu` | `<span class="golem-menu">` | Separates inline menu items with standard `>` arrows
| `footnote` | `<sup class="golem-footnote-ref">` | Wraps superscript anchors linking to the bibliography segment
| `footnoteref` | `<sup class="golem-footnote-ref">` | Links named subsequent references back to the primary index
| `ref` (link) | `<a href="{target}" target="{window}">` | Incorporates security `rel="noopener"` if `window="_blank"`
| `span` (strong) | `<strong>` | Bold inline text
| `span` (emphasis) | `<em>` | Italic inline text
| `span` (monospaced) | `<code>` | Inline code
|===

=== 8.2 Footnote Rendering Protocol
Golem's `HtmlRenderer` collects and resolves footnotes dynamically across each document during traversal:

1. **Discovery:** When an inline node of type `footnote` containing content is first encountered, Golem assigns it a sequential 1-indexed number.
2. **Buffering:** It registers the footnote definition (retaining its index, target ID, and inner content nodes) in a document-level `self.footnotes` accumulation buffer.
3. **In-Text Callout:** It renders a linking superscript callout at the point of definition:
+
[source,html]
----
<sup class="golem-footnote-ref" id="_footnote_ref_1"><a href="#_footnote_1">1</a></sup>
----
4. **Subsequent References:** When a named footnote reference (`footnoteref:[id]`) is encountered without content, Golem queries the buffer for the existing ID and renders a standard back-link superscript using that node's assigned index.
5. **Bibliography Generation:** At the conclusion of document body translation, Golem evaluates `self.footnotes`. If footnotes are present, it renders a semantic container and appends it to the bottom of the body HTML:
+
[source,html]
----
<section class="golem-footnotes" role="doc-endnotes" aria-label="Footnotes">
  <hr class="golem-footnote-divider" />
  <ol>
    <li id="_footnote_1" role="doc-endnote">
      <span class="golem-footnote-num">1.</span>
      <span class="golem-footnote-body">This is the footnote content.</span>
      <a href="#_footnote_ref_1" role="doc-backlink" class="golem-footnote-backlink" title="Jump back to reference">&#x21A9;</a>
    </li>
  </ol>
</section>
----

=== 8.3 Slugification Protocol
To ensure stable cross-references (`inline_xref`), section IDs are generated deterministically:

1.  Convert title string to lowercase.
2.  Replace any non-alphanumeric characters (excluding hyphens) with empty space.
3.  Replace spaces and underscores with a single hyphen `-`.
4.  Strip leading/trailing hyphens.

=== 8.4 Server-Side Syntax Highlighting (`golem/highlighting.py`)
Golem performs zero-JavaScript, server-side syntax highlighting of source code listings via Pygments (`pygments>=2.18`):

*   **Custom Color Palettes:** Handcrafted `FiredClayStyle` (light mode) and `FiredClayDarkStyle` (dark mode) matching Golem's workbench aesthetic.
*   **HTML & CSS Generation:** Generates tokenized HTML blocks and injects combined light/dark media-query scoped Pygments CSS (`PYGMENTS_CSS`) into page layouts.
*   **Language Aliases:** Standardizes aliases (e.g., `py`/`python3` -> `python`, `js`/`ts` -> `javascript`/`typescript`, `sh`/`zsh` -> `bash`, `adoc` -> `asciidoc`).

== 9. Chameleon Templates & Layout Skeletons

Golem coordinates structure and layouts using the _Chameleon_ templating engine, which executes compiled TAL (Template Attribute Language) templates at high speed.

=== 9.1 Base Layout Slots
The standard skeleton template (`golem/templates/default/skeleton.pt`) exposes these slots:

[source,xml]
----
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml"
      xmlns:tal="http://xml.zope.org/namespaces/tal"
      xmlns:metal="http://xml.zope.org/namespaces/metal">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title tal:content="site_title">Golem Documentation</title>
  <link rel="stylesheet" href="static/golem.css" />
  <metal:define-slot name="head" />
</head>
<body>
  <div id="golem-container">
    <header id="golem-header">
      <div class="header-logo" tal:content="site_name">Golem</div>
      <metal:define-slot name="header" />
    </header>
    <div id="golem-body">
      <aside id="golem-sidebar-left">
        <nav class="golem-nav">
          <metal:define-slot name="navigation" />
        </nav>
      </aside>
      <main id="golem-content">
        <article class="golem-doc">
          <metal:define-slot name="content" />
        </article>
      </main>
      <aside id="golem-sidebar-right">
        <nav class="golem-toc">
          <metal:define-slot name="table-of-contents" />
        </nav>
      </aside>
    </div>
    <footer id="golem-footer">
      <p>&#169; <span tal:replace="site_author">Author</span>. Built with Golem.</p>
      <metal:define-slot name="footer" />
    </footer>
  </div>
</body>
</html>
----

== 10. Developer Server & SSE Live-Reload Protocol

Golem serves compiled document folders via `golem serve` to enable real-time local authoring.

=== 10.1 Multi-Threaded HTTP Server
Golem hosts static files from `build.output_dir` using Python's built-in `http.server.ThreadingHTTPServer` bound to a custom request handler. This permits concurrent handling of static asset transfers and Server-Sent Events (SSE) reload connections.

=== 10.2 Server-Sent Events Reload Loop
*   **The Endpoint:** The dev server hosts an SSE endpoint under `/golem-reload`.
*   **Client Script:** During serving, Golem's build engine automatically injects a tiny Javascript listener snippet into the compiled skeleton head:
+
[source,javascript]
----
(function() {
  const sse = new EventSource('/golem-reload');
  sse.onmessage = function(event) {
    if (event.data === 'reload') {
      console.log('[Golem] File change detected. Reloading...');
      window.location.reload();
    }
  };
})();
----
*   **Server Watcher:** The dev server maintains a list of open SSE socket connections. In the background, a file-system monitor polls files inside `content/` for SHA-256 or timestamp updates.
*   **Trigger:** Once a change is found, Golem launches an incremental rebuild of invalidated compilation DAG nodes and immediately writes `data: reload\n\n` to all active SSE streams, causing browser tabs to refresh instantly.

== 11. CLI Commands

The `golem` command-line utility routes user actions using a standard Click-based interface with global `-C/--directory` and `--version` support.

=== 11.1 Core Commands
*   `golem init [--template=<type>] [--output-dir=<dir>] [-C <dir>]`
    *   Creates a standard directory structure and basic `golem.toml` (or `[tool.golem]` in `pyproject.toml`).
    *   Profiles: `package` (default, standard library layout), `site` / `book` / `simple` (scaffolds `templates/` and `static/css/custom.css`).
    *   NOTE: Named profiles `library`, `cli`, `paper`, and `blog` currently map to the generic package or site skeleton. Differentiated scaffolding is tracked in https://github.com/webmaven/golem/issues/9[GitHub issue #9].
*   `golem new <type> <name> [-C <dir>]`
    *   Generates a structured `.adoc` file with pre-populated header attributes (`:golem-type:`, `:author:`, `:date:`), title, and introduction section.
    *   Example: `golem new post "Hello World"` creates `content/hello-world.adoc`.
*   `golem build [--config=<path>] [--clean] [--strict] [-v/--verbose] [-q/--quiet] [-C <dir>]`
    *   Runs the incremental compiler, building static pages into the configured output folder (`dist/` by default).
    *   Flags: `--clean` purges the output directory and cache; `--strict` treats warnings as fatal errors; `-v` enables debug logging; `-q` silences non-error output.
*   `golem serve [--port=<port>] [--host=<host>] [--strict] [-C <dir>]`
    *   Invokes an initial build, launches the multi-threaded HTTP web server, activates SSE reload streaming, watches source directories, and injects real-time diagnostic error overlays if compilation errors occur.
*   `golem plugins [--json] [-C <dir>]`
    *   Inspects and lists all active built-in, setuptools entrypoint, and local plugins, showing enabled/disabled status and discovery sources. Supports `--json` machine-readable output.
*   `golem themes [--json] [-C <dir>]`
    *   Inspects and lists the currently active theme alongside all available built-in, local (`themes/`), and entry point themes. Supports `--json` machine-readable output.

=== 11.2 Plugin-Registered Commands
*   `golem doctest [paths...] [-m/--mode=<mode>] [-s/--source=<pkg_or_file>] [-v/--verbose] [-x/--fail-fast]`
    *   Registered via `golem.plugins.doctest`. Walks AsciiDoc source files or Python docstrings, isolates Python code listing blocks, and executes them with sequential state preservation.
    *   Modes: `explicit` (default, runs blocks marked with `role="test"`), `eager` (runs all Python listing blocks sequentially), `auto`.
    *   Flags: `-s/--source` to target Python packages/files for docstring testing; `-x/--fail-fast` to stop on first failure; `-v` for verbose output.
*   `golem apidoc [package] [-o/--output=<dir>] [-s/--docstring-style=<style>]`
    *   Registered via `golem.plugins.apidoc`. Introspects Python packages and generates standard AsciiDoc API reference documentation pages.
